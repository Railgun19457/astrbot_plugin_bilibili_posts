# B站动态检测

![:name](https://count.getloli.com/@astrbot_plugin_bilibili_posts?name=astrbot_plugin_bilibili_posts&theme=miku&padding=7&offset=0&align=top&scale=1&pixelated=1&darkmode=auto)

AstrBot 插件：定时检测指定 B站用户动态，并将新动态以 Pillow 概览图和原始链接推送到指定会话。

## 功能概览

| 能力 | 说明 |
| --- | --- |
| 定时检测 | 按配置间隔自动检测指定 UID 的新动态 |
| 手动推送 | 通过 `/哔哩动态 [数量]` 推送每个 UID 的最新 N 条动态 |
| 多模板 | 支持多个检测模板，每个模板可独立配置 UID、动态类型和目标会话 |
| 类型过滤 | 支持视频投稿、图文/图片、纯文字、转发和其他动态类型 |
| 图片概览 | 使用 Pillow 渲染动态概览图，展示作者、正文、图片/视频卡片、互动统计等信息 |
| 原始链接 | 可附带动态原始链接，转发动态也可附带原动态链接 |
| 状态去重 | 记录已推送动态 ID，避免自动检测重复推送 |
| 首次基线 | 新模板首次运行只建立基线，不会一次性推送历史动态 |

## 使用方式

插件使用 AstrBot 框架指令系统，触发方式遵循 AstrBot 平台设置（例如命令前缀、唤醒词、@机器人或私聊）。

| 指令 | 说明 |
| --- | --- |
| `/哔哩状态` | 查看自动检测状态、启用模板数、检测 UID 数、下次检测时间和最近结果 |
| `/哔哩动态` | 按配置默认数量推送每个 UID 的最新动态 |
| `/哔哩动态 5` | 推送每个 UID 的最新 5 条动态，数量范围为 `1-20` |

## 行为说明

- 自动检测启用后，AstrBot 启动或插件加载后会按 `check_interval_minutes` 周期检测。
- 自动检测首次遇到模板和 UID 组合时，只会把已抓取动态标记为已读，不会刷屏推送历史动态。
- 手动执行 `/哔哩动态 [数量]` 会直接推送最新动态，并把这些动态写入已读状态。
- 图片概览和原始链接会分开发送：每条动态先发送图片，再发送链接，然后才处理下一条动态，减少多条推送时的对应关系混乱。
- 单个 UID 拉取失败不会中断其他 UID，错误会写入日志和最近结果。
- 若概览图渲染失败，插件会自动降级为文本摘要和链接。

## 配置项

### 基础配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enable_auto_check` | `true` | 是否启用自动检测 |
| `check_interval_minutes` | `30` | 检测频率，单位分钟；建议不要过低，避免触发 B站风控 |
| `request_timeout_seconds` | `20` | 获取动态和下载渲染素材的网络超时时间 |
| `page_limit` | `1` | 每个 UID 每轮最多抓取的分页数，范围 `1-5` |
| `default_command_dynamic_count` | `3` | `/哔哩动态` 未指定数量时的默认推送条数，范围 `1-20` |
| `templates` | `[]` | 动态检测模板列表 |

### 模板配置

每个模板用于定义一组 UID 的检测规则和推送目标。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `name` | `默认动态模板` | 模板名称，用于日志和状态区分 |
| `enabled` | `true` | 是否启用当前模板 |
| `users` | `[]` | 要检测的 B站 UID 列表，可填写纯 UID，也可填写包含 UID 的字符串 |
| `dynamic_types` | 视频投稿、图文/图片、纯文字、转发 | 要推送的动态类型 |
| `forward_options` | 渲染图、原始链接 | 推送内容选项 |
| `session_umos` | `[]` | 目标会话 UMO 列表，可在目标会话发送 `/sid` 获取 |

## 动态类型

`dynamic_types` 支持以下选项：

| 配置值 | 说明 |
| --- | --- |
| `视频投稿` / `video` / `视频` / `av` | 视频投稿 |
| `图文/图片` / `image` / `图片` / `图文` / `draw` | 图文或图片动态 |
| `纯文字` / `word` / `文字` | 纯文字动态 |
| `转发` / `forward` | 转发动态 |
| `其他` / `other` | 其他未归类动态 |

## 推送内容选项

`forward_options` 支持以下选项：

| 配置值 | 说明 |
| --- | --- |
| `渲染图` / `render_image` / `概览图` | 生成并发送 Pillow 动态概览图 |
| `原始链接` / `original_link` | 发送动态原始链接；转发动态会额外发送原动态链接 |

同时启用两个选项时，每条动态会先发送概览图，再发送链接文本。

## 持久化说明

插件会在数据目录下维护 `state.json`，用于保存：

- 每个模板和 UID 组合的初始化状态；
- 已推送或已建立基线的动态 ID；

这意味着：

- Bot 重启后不会立即重复推送已经记录的动态；
- 每个状态键最多保留 500 个动态 ID，避免状态文件无限增大；
- 修改模板名称或模板顺序可能会改变状态键，必要时会重新建立基线。

## 依赖

依赖写在 `requirements.txt` 中：

- `bilibili-api-python`：获取 B站动态数据；
- `aiohttp`：`bilibili-api-python` 相关异步网络依赖；
- `Pillow`：渲染动态概览图。

## 注意事项

- 建议将 `check_interval_minutes` 设置为 `30` 分钟或更高，避免频繁请求触发 B站风控。
- `session_umos` 必须填写有效目标会话，否则模板会被跳过。
- B站接口可能随时变化，若出现长期抓取失败，请先检查依赖版本和插件日志。
- Windows 环境下会优先使用微软雅黑等系统字体；Linux 环境建议安装可显示中文和 emoji 的字体，以获得更好的概览图效果。
